localhost:9211
(CORS proxy)		 RUM CORS proxy (rum-proxy.py). Accepts browser requests, adds CORS headers, then forwards server-side to Local APM and ECH ES1 APM — both of which block browser CORS because RUM is disabled by default. EP1 in the tool. Start with: python3 rum-proxy.py from the OTEL directory. Required for browser → Local APM and browser → ECH ES1 to work. Run this first
localhost:8200
(elastic-agent APM)		 Local APM server managed by elastic-agent Docker container. Accepts OTLP and RUM intake v2 — but browser CORS is blocked because RUM is not enabled in the Fleet policy. Reached via the proxy only. Direct browser access blocked by CORS. To enable direct access: turn on RUM in Fleet → APM integration → enable RUM → allow origins: * Via proxy only
c204b3ce….apm.cloud.es.io
(ECH ES1 APM)		 ECH ES1 APM server in GCP us-central1. Bearer token auth. Browser CORS blocked — RUM must be enabled in the deployment settings for direct access. Reached via the proxy. Auth header is added server-side by the proxy, so no secret in the browser. Via proxy only
localhost:8080 OTel demo app frontend (React). Served by the demo's frontend container. Optional: fetch calls to this origin create distributed traces linking RUM to backend spans. Add to distributedTracingOrigins. Optional correlation
localhost:4317 / 4318 OTel collector inside the demo stack. Accepts OTLP gRPC / HTTP. Not used by RUM tool directly. The browser cannot reach gRPC. Use OTLP HTTP on 4318 if switching to OTel JS SDK. Not used
localhost:4320 EDOT otelcol inside elastic-agent (Flow 5). Accepts OTLP gRPC. Not reachable from browser. Relevant only for backend / server-side instrumentation. Not used
*.ingest.*.elastic.cloud ECH / serverless managed OTLP input. Accepts OTLP HTTP only. Serverless has no RUM intake. ECH managed OTLP accepts OTLP, not APM intake v2. Cannot be used by this RUM tool. Not compatible
Fully standalone (no demo needed):
All actions except "Demo app integration" mode generate synthetic APM events and POST directly to whichever APM endpoints are enabled. The OTel demo app does not need to be running. Works with just a local APM server (port 8200) or ECH APM server.
Demo app integration (optional):
Enable the toggle in the config bar to have the Recommendations action also fetch localhost:8080/api/recommendations with a traceparent header. When the OTel demo is running, this correlates browser spans to backend microservice spans in the APM Service Map.
